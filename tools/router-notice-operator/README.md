# Finite historical-notice operator

Platform-foundation maintenance tool, not an installed lane consumer. It approves only a reviewed finite SSA-to-Horus coordination manifest using the existing operator credential. It cannot acknowledge notices, close product work, grant a general mailbox capability, or revive a service.

Dry-run is the default. Supply an absolute owned private regular request file and its independently reviewed SHA256. Unknown fields, foreign actor/recipient, duplicate entries, changed bytes, public files and expired plans are rejected. `--apply` additionally requires the exact qualified canonical revision and image SHA256.

Before credential access, all percentage and tag routes must select that revision, the observed generation must match, Ready and RoutesReady must be true, and the revision image must match. After credential access the helper repeats the route checks and requires the same generation before submitting. This is a bounded observation, not a GCP configuration lock. The operator must maintain a no-route-change interval through approval and subsequent notice readback. Any rollback during that interval must retain the same reconciliation namespace guards; do not return to a guard-incompatible image after activation.

The fixed existing project/account retrieve the existing bootstrap secret directly into this process; no new credential, IAM, security setting or account configuration is provisioned. Each gcloud child forces HTTP logging off and file logging disabled, overriding inherited/persistent tracing settings without changing parent configuration. The SDK uses explicit memory-only sessions, with ordinary authenticated transport and actual registered runtime identity. Neither bearer nor derived HMAC session is exported to environment/argv/files or shared with another lane. Existing session caches are neither read, pruned nor deleted.

Compile with the normal Ma'at front door, then use the prebuilt maintenance CLI for the authorized coordination operation as the actual registered SSA operator. Registration and router coordination do not require a compute lease. Do not run approval as an ungranted headless compute worker, change its declared surface or grant answering rights to make approval pass; its refusal is correct. Keep builds/tests and any service launches under their normal admission controls.

Run the default dry-run first, retain exact source/test review and serving-state evidence, then apply once. After approval, the ordinary SSA CLI must use its own scoped identity and `reconcile-notice --request ... --apply` for each exact approved historical notice. Preserve original rows/audit history and keep excluded service/product obligations open. An error or uncertain response is not permission to widen authority or bulk-close anything; inspect the typed result/readback before retrying an identical operation.

Tests include closed-plan rejection, dry-run no-cloud behavior, route/image refusal before secret access, changed-route refusal after credential retrieval, expiry, sanitized errors, and bounded stdout including io.Copy. The routerstore memory-only SDK fixture exercises a real session mint and typed approval against an isolated local server, including poisoned preexisting cache preservation. No tests use production credentials or services.
