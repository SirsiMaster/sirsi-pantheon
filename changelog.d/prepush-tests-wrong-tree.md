- **CI: pre-push gate now names a HEAD/pushed-sha mismatch, the case its 2026-08-06 dirty-tree warning didn't cover** (claude-home, 2026-08-08). `.githooks/pre-push` runs fmt/vet/build/test against the checkout's working tree, not against the sha it is actually pushing — PR #626 warned about this when the tree is *dirty*, but a **clean** tree gives no signal at all when the pushed sha simply isn't `HEAD` (`git push origin <sha>:<branch>` from a checkout sitting on a different branch, e.g. a merge commit resolved in a temp worktree and pushed from the primary checkout). Measured 2026-08-07: pushing #663/#664's resolved merges this way produced 6 failing `cmd/sirsi` tests that were a false signal — the same packages passed cleanly in the worktree that actually held the pushed commit; the primary checkout's `HEAD` was on an unrelated branch. Adds a loud warning comparing `PUSH_LOCAL_SHA` against `git rev-parse HEAD` before the test stage, same shape and placement as the existing dirty-tree check. Verified both directions: a mismatched sha (using a real ancestor commit against the current checkout) prints the warning; pushing `HEAD` itself stays silent. No test framework exists for this hook (confirmed by precedent — #626 shipped the same way, a bash script with no bats/shell-test suite); verification is a direct before/after run against a real worktree instead.
