### Added

- **`RunInformer` refuses explicitly on a `RemoteStore` backend instead of running an unauthenticated cross-host push.** rs-37 task 7's host-pin predicate (`InformerHostAuthorized`, commit `725dd38c`) is in-process only — the router service has no authenticated per-host dispatch-authorization channel over the wire yet. A process that resolved a `*routerstore.RemoteStore` (a client of a router service elsewhere, not the authoritative backend host) would otherwise subscribe and dispatch locally with no NC1/NC2 refusal path at all. `RunInformer` now type-checks its resolved store before subscribing to any lane and returns the new `router.ErrInformerRemoteBackendUnsupported` immediately. Per SSA ruling `20261007-230828` (rs-37 task 7): build/verify the in-process predicate now, and record task 7 live M1 verification as blocked by this wiring rather than claiming it. `go test ./internal/router/...` covers both the refusal (RemoteStore) and the unaffected local-backend path (SQLite, empty registry).
