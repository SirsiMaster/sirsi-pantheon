- **Ledger tasks finish only on a router-checked receipt.** `sirsi router task complete --receipt` takes `pr:owner/repo#N` (merged, merge commit on the default branch), `ci:owner/repo#RUN@SHA` (run succeeded on exactly that commit), `tag:owner/repo@TAG` (tag exists, every check run on its commit passed) or `maat:RUN` (host-attested: the CLI hashes a clean Ma'at run's `terminal.json`; the service records it, it cannot verify it). The router verifies PR/CI/tag receipts itself against GitHub with the read-only `SIRSI_ROUTER_GITHUB_TOKEN`, and fails closed when it cannot. Free text is refused; `--result-ref` remains only as a deprecated alias for a valid receipt. `task add` can no longer create a `done` task. The receipt is recorded beside the task (state `task-receipt:<agent>/<task>`, unwritable through generic state). New terminal status `canceled` (owner-only, with reason) never counts as done. `sirsi router task recheck-receipts` and the supervisor duty `receipt-recheck` (6h) re-verify receipts and reopen a task whose receipt is now proven false; network errors never reopen. Owner sign-off (`CompleteTaskByOwner`) and `CancelTask` are store methods that are deliberately not served remotely. Refs: owner decision 2026-11-02 "Router-checked receipt", ADR-057.
