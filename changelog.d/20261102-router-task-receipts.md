- **Ledger tasks finish only on a router-checked receipt.** `sirsi router task complete --receipt` takes `pr:owner/repo#N` (merged, merge commit on the default branch), `ci:owner/repo#RUN@SHA` (run succeeded on exactly that commit), `tag:owner/repo@TAG` (tag exists; every check run on its commit, across all pages, finished with no failure and at least one success) or `maat:RESERVATION-ID` (the router's own Ma'at ledger: held by the task's agent, released, exit 0). The router verifies PR/CI/tag receipts itself against GitHub with the read-only `SIRSI_ROUTER_GITHUB_TOKEN` and fails closed when it cannot. Receipts are bound: repos must belong to `ReceiptRepoOwners` (default `SirsiMaster`), `.`/`..`/empty path segments are refused, and one receipt proves one task. Free text is refused; `--result-ref` remains only as a deprecated alias for a valid receipt. `task add` can no longer create a `done` task. The receipt is recorded beside the task (state `task-receipt:<agent>/<task>`, unwritable through generic state). `sirsi maat release <id> --exit-code N` records the run's exit status on the reservation (`exit_code`). New terminal status `canceled` (owner-only, with reason) never counts as done. `sirsi router task recheck-receipts` and the supervisor duty `receipt-recheck` (6h) re-verify PR/CI/tag receipts and reopen a task only on positive proof of falsity — a bare 404 or a network error never reopens — guarded on the exact receipt read. Owner sign-off (`CompleteTaskByOwner`) and `CancelTask` are store methods that are deliberately not served remotely. Refs: owner decision 2026-11-02 "Router-checked receipt", ADR-057.
