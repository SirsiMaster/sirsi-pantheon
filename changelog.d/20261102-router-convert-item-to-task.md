- **`sirsi router convert <item-id> [--agent A] [--task ID]`: turn a router item into ledger work.** One transaction closes the open item with the result `converted to task <agent>/<task-id> by <actor>` and adds a `pending` task: subject from the item title, outline naming the item and its sender, commissioned by the sender. If either write fails, neither lands. Re-running it on the same item returns the same task. An item closed any other way is refused. The task id defaults to the item id. Authority is the same as `router close` (owner-addressed items are refused, and another lane's item needs `close:any`). Over the router service, the new `ConvertItemToTask` RPC is in the lane API: a scoped token may convert only items addressed to it, onto its own ledger. The server records the actor from the authenticated session, never from the client, and the method counts as answering an item for the headless-worker hold. Refs: ADR-062, LANE_SCOPED_TOKENS, ROUTER_TASK_LEDGER.
