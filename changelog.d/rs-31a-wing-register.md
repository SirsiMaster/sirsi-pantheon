- **`sirsi router wing register <file>` (rs-31a).** Schema-validates a Stack Lab wing record against `contracts/stacklab/v2/wing.schema.json` (reusing `internal/stacklab.ValidateWing`/`ContentSHA256`, no new validation logic) and persists it atomically in a new `wings` table (SQLite + Postgres schema v24): idempotent on identical bytes (re-registering the same wing id with the same content returns the existing receipt), rejects a conflicting identity (`ErrWingConflict`) rather than silently overwriting. Caller-authority binding (rs-31b: tying the caller to an independently-established project/repo authority, not a self-declared field) and canonical-path containment/peer-policy enforcement (rs-31c) are deliberately NOT in this change — separate sub-builds the task ledger (`rs-31-wing-schema-enforcement`) already splits out, pending SNE design review before anything in that admission-control surface ships.
