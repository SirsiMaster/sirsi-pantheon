- Threads: new reversible `quarantined` status for stale thread records. `sirsi thread quarantine --thread <id> | --stale [--stale-after 1h] [--dry-run]`, `sirsi thread unquarantine --thread <id>`, and `sirsi thread list --quarantined`. Quarantined records are never reaped or pruned, are excluded from live/stale counts, attended-session detection, armed credit and wake targeting, and are listed separately by `sirsi router doctor`. A heartbeat or re-register from the same thread releases the record ("proved alive"). The router service's thread CAS accepts the equal-timestamp transition into and out of `quarantined` (no schema change). `router board-serve` now waits for its own thread close on SIGTERM so Cloud Run instances stop leaving stale `router-board` records. See `docs/user-guides/thread-quarantine.md`.
