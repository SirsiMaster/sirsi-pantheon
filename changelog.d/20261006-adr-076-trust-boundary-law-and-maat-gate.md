- **Trust-Boundary Law (ADR-076, Universal Rule 32) and `sirsi maat gate`** (claude-finalwishes-m1, owner-directed 2026-10-06: "fix and rework those gaps once and for all — not just for FinalWishes"). Over 2026-10-05/06 every agent commit in FinalWishes was caught by the security sweep on the same eight defect classes — client numbers as loop/allocation bounds, unbounded output, client-sent provenance trusted, a new path skipping sibling gates, merge-instead-of-replace on persisted PII maps, PII on viewer-readable paths, silent drops and meaning-changing normalisation, and verifiers whose exit status was lost in `… | tail && push` plus self-admitted exemptions. ADR-076 names them A–H as binding law with the checklist every slice reports one line per item; `CLAUDE.md`/`PANTHEON_RULES.md`/`AGENTS.md` §1 gain the identical Universal Rule 32. `sirsi maat gate` (`internal/maat/trustboundary`) runs a repo's traceability verifier with its own exit status as the verdict, refuses any growth of `scripts/traceability-historical-exemptions.txt` in the pushed range, runs gitleaks over the range, and lints changed Go/TS/shell files with A–H heuristics (allowlist `trust-boundary: <reason>`); `--pre-push` reads git's ref lines so any repo adopts it with one hook line, `--report` prints the checklist skeleton, `--install` arms `core.hooksPath` (one call covers a repo's worktrees). Fixtures in `testdata/` reproduce each class with minimal Go/TS/shell; the gate test pins that a verifier printing "passed" and exiting 1 still fails the gate. Pantheon's own pre-push now runs the lint on pushed files. Refs: ADR-076, ADR-004, PANTHEON_RULES A6/A7/A17/A28; Changelog: Unreleased
