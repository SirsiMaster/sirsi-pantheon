# Relay-owned outbox observation

Service-owned outboxes remain private. A GUI permission denial is evidence about the observer's access, not proof that delivery failed or the queue is empty. This corrective projection adds no daemon, listener, credential, key, role, or alternate router authority.

## Producer and reader contract

After existing relay startup trust validation, the **existing relay loop** samples at most once every five seconds. It publishes `.relay-outbox-health-v1.json` using an exclusively created new descriptor and atomic replacement. The snapshot contains only version, root device/inode, producer UID, interval start/end, enumeration/completeness, per-lane existing name, `observed|unavailable|absent`, optional count, and closed error codes. No request IDs, bodies, tokens, or raw filesystem errors appear. An observed zero has a present count; an unavailable or absent outbox has no count. An absent outbox is an observed namespace absence, not a missing lane in a partial listing.

Names are scanned incrementally, with limits of 256 lanes, 16,384 directory entries across the whole scan, 1 MiB of names, and a 100 ms elapsed-time budget checked around directory operations. This is not a preemptive deadline for a blocked filesystem syscall. Serialized metadata is capped at 131,072 bytes. A changing directory, malformed layout, permission failure, or exhausted budget withholds affected evidence. Eligible siblings remain visible, but an aggregate count is present only when enumeration and **all** lane observations are complete. Counts are cooperative interval samples, not transactional queue state or delivery acknowledgments.

The reader independently opens and validates the root/parent without following physical path components. Private same-user roots use that existing root policy. The existing protected service profile `/private/var/sirsipantheon/relay` requires the OS-resolved `_sirsipantheon` UID on both root and its protected parent, including when the reader happens to run as that UID. Group membership is never a producer identity. Other foreign-owner configurations are unavailable, not implicitly trusted.

Metadata ownership must match the independently expected producer. With an explicitly configured trust group, both root and new summary use the **exact resolved gid**, and the new summary is exactly `0640`. Without a declared group the private root is `0700` and the new summary is exactly `0600`. There is no fallback to the process's ambient group (such as staff). Extended ACLs on the summary are refused. Only the exclusively created new artifact receives `fchown`/`fchmod`; existing paths, outboxes and ACLs are not changed by health publication or observation. The existing bootstrap trust helper's startup behavior is unchanged.

Darwin ACL verification calls supported libSystem `fgetattrlist` through a small cgo bridge using SDK types/constants and a bounded call-local buffer. A Darwin build without cgo cannot establish absence of extended ACLs and refuses summary publication/acceptance rather than falling back to mode bits or a direct syscall. This projection limitation does not stop relay transport. The owned native ACL fixture changes only its empty temporary file, never an existing spool or user file.

Readback requires a no-follow regular file, link count one, exact UID/gid/mode, bounded bytes, duplicate-free exact-key JSON, unique valid lanes, valid state/count/completeness relationships, and root/name/descriptor continuity after reading. The reader checks age at **read completion**, not command start. Evidence older than 15 seconds, more than two seconds in the future, or spanning more than one second is unavailable. A fresh node-status collection never renews an old producer timestamp. These are point-in-time cooperative continuity checks, not isolation against a hostile same-UID actor.

Publication failures never stop relay forwarding. A failed publisher disables this relay instance's projection and any prior snapshot expires. A newly created temporary leaf may remain as explicit cleanup debt; the publisher never unlinks an unknown replacement. No request is replayed, drained, or deleted for health collection.

## Guided resolution

Node-status carries direct observer access separately from retry state/source/interval, plus explicit inventory coverage. Optional missing-publisher capability does not invalidate a complete direct inventory. Incomplete or expired coverage remains unknown even when some individually eligible rows exist. Ra can therefore show **Service-managed private outbox · N retries observed · updated …**, including explicit zero, while direct payload access remains private. Partially covered lanes remain individually visible without a partial total. Expired direct-readable rows remain visible as unknown/retained observations rather than disappearing into a healthy summary. Row and coverage expiry use the producer interval start when present, retaining the exact fifteen-second bound. Counts never assert that retries succeeded.

**Refresh relay observation** invokes the existing forced node-status read, then checks producer freshness rather than merely the board collection time. Read failure retains prior evidence without refreshing its time. If the publisher is absent, the prerequisite is an owner-managed update through the existing selected-service lifecycle. The GUI does not restart services, change permissions, or attempt a raw lifecycle fallback.

**Repair this outbox** appears only for a recent same-user read-only preflight. Every row (including readable verification rows) carries the opened canonical spool and root device/inode. The confirmation freezes and displays immutable agent plus root scope; replacing the offer with another spool or root identity is refused before launch, including at the typed capture's final authorization check. The existing typed `router relay repair-outbox --agent … --spool …` command independently repeats its retained no-follow checks at mutation time. Service-owned, symlinked or otherwise unsupported roots never receive a repair offer. After confirmation, typed command capture records whether the operation actually exited successfully; a forced board readback separately verifies a fresh, post-operation, directly readable outbox under the **same agent and exact root scope**. A fresh same-agent observation from another spool cannot verify the approved repair. Command success without that evidence is **verification unavailable**, not green. Failed commands remain failed even if readback succeeds. Unsupported or uncertain cases retain the existing Ma'at guided-resolution route.

Native consent passes the approved root device/inode through paired `--expected-root-device` and `--expected-root-inode` flags. Go compares the retained root descriptor and its retained-parent namespace entry immediately before leaf mutation; a valid replacement root at the same path is refused. Legacy explicit CLI callers without either flag retain existing behavior; a partial pair is refused. This cooperative point-in-time check is not atomic exclusion of hostile same-UID leaf replacement. Ambiguous or different-scope readback cannot establish success.

## Qualification and limits

Prepared source selectors: `TestRelayObservation` in `internal/routerstore`, existing `TestSpoolOutboxHealth`/`TestRepairSpoolOutbox` coverage, and native `RelayObservationTests`. Fixtures use owned roots, synthetic service-policy metadata, inert queue markers, and per-call command/refresh doubles. They cover zero vs missing, partial coverage, duplicate/case-alias JSON, root/file substitution, nonregular files, stale-at-read-completion, exact group policy, no payload opening, unsupported repair, typed command order, and failed verification.

Source checkpoints are **unqualified** until Main admits normal/race/native qualification and independent review. No installed publisher, hardware, permission migration, all-lane delivery, or cross-host outcome is claimed by this source change. OS extended-ACL inspection and exact metadata-group creation require the owned native filesystem fixtures to qualify the Darwin implementation; unknown inspection fails closed before count bytes are written. Darwin uses descriptor-based `fgetattrlist(ATTR_CMN_EXTENDED_SECURITY)`, not the protected `com.apple.system.Security` xattr. ABI/reference sources: the macOS SDK `sys/attr.h`/`getattrlist(2)` and [Apple's attribute packer](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/vfs/vfs_attrlist.c).
