## Supported path

The inherited dispatcher binding identifies the wake controller. It is not the
new consumer's actual PID/thread. Do not adopt another live session's runtime.
Registration and queue coordination are available without a compute lease; use
one standalone installed CLI command per tool call. Do not prepend discovery,
echo or a shell pipeline that changes classification.

For payload work use the existing `sirsi-maat-run --agent <own-id>
--register-executor --work <exact-work> --timeout 300 -- <program> <args>`.
The supervisor clears the inherited thread selector for its own control calls,
registers its actual PID as a fresh worker on the destination, then verifies
that actual identity before admission and spawning. It does not require a
one-shot Claude process to pretend to be an interactive persistent session.
Normal refusal, cleanup, current principal and lease fences still apply.

`setsid` alone does not reparent a process; actual controller exit/reparenting
requires PID/start/PPID evidence. Do not weaken ancestry checks based on that
assumption. Do not reset dispatch backoff or spawn a duplicate for diagnosis.
