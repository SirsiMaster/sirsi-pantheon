# Pantheon Commercialization Gate

**Classification:** `platform-foundation` today; an SNE tuple may be called a `pilot` only after its device-specific launch qualification and clean-host workflow pass.  
**Portfolio authority:** `/Users/thekryptodragon/Development/COMMERCIALIZATION_GATE.md` and `/Users/thekryptodragon/Development/SIRSI_MANIFESTO.md`

## Buyer / User

- Primary user: a Mac owner or organization that wants private local AI without manually assembling runtimes, models, permissions, and recovery procedures.
- Operator: the person responsible for keeping the Mac usable, secure, updateable, and diagnosable.
- Product consumer: Nexus and other authorized Sirsi applications that select an admitted local model through Pantheon's authoritative state.

## Pain

Local inference products commonly expose a fast demo while leaving users to manage incompatible models, missing files, memory pressure, swap, unsigned updates, stale processes, opaque failures, and accidental cloud fallback. The repeated cost is lost time, broken trust, unusable machines, and results that cannot be reproduced after restart or upgrade.

## Primary Workflow

1. Open Pantheon and view models compatible with this exact Mac.
2. Review model identity, precision, execution mode, memory requirement, qualification status, support status, context/cache capability, and license terms.
3. Install one exact model tuple transactionally from a signed source.
4. Start its exact signed runtime after package, model, memory, swap, and readiness admission.
5. Use the model through Nexus or the stable local OpenAI-compatible API.
6. Understand failures and recover without silent changes to model, precision, processor, framework, execution mode, or cloud destination.
7. Update, roll back, remove, uninstall, or export privacy-safe support evidence.

## Willingness To Pay

This capability supports acquisition and retention because it turns local AI from an expert-only assembly project into an owned, governed product. Nexus can charge for the higher-order selection, policy, fleet, and infrastructure experience while Pantheon demonstrates trustworthy local operations and reduces support cost, downtime, and data-boundary risk.

## Trust Boundary

- Model weights, prompts, generated text, KV caches, and local capability credentials remain on the user's Mac unless the user explicitly selects a different policy-visible route.
- Pantheon may read signed catalogs, package/model manifests, resource state, process health, and privacy-safe diagnostic identities required to operate SNE.
- Install, license acceptance, model removal, catalog update, rollback, and restart are explicit and auditable.
- Serving prohibits silent Python, CPU, cloud, model, precision, framework, processor, account, or runtime fallback.
- Support exports exclude conversations, generated text, model data, caches, credentials, environment values, network configuration, and machine identifiers.

## Operational Owner

Pantheon owns discovery, signed admission, verified acquisition, one-copy residency, memory/swap care, lifecycle, readiness, diagnostics, update, rollback, removal, and recovery. SNE owns inference execution. Nexus owns product intent and model selection. Support requires exact package/runtime/model/manifest identity, device/OS tuple, resource admission, failure code, recovery guidance, and reproducible evidence hashes.

## Done Evidence

Product closure requires all of the following for each supported device tuple:

- Signed catalog and source provenance; verified transactional checkout and license receipt.
- Relocatable package closure with exact hashes and no ephemeral dependency.
- Prompt-logit, generated-token, terminal-logit, streaming-equivalence, quality, context, cancellation, timeout, stop, concurrency, and fairness evidence.
- TTFT, prompt throughput, engine and visible tok/s, p50/p95 token latency, end-to-end latency, memory, swap, power, thermal, and complete session provenance against governed comparators.
- Fresh20, fresh100, varied100, two-hour and overnight soak, sleep/wake, reboot, crash, memory-pressure, AC, and battery evidence before public claims.
- Coherent first, empty, progress, success, failure, recovery, update, rollback, removal, and uninstall states across authoritative Pantheon surfaces.
- Keyboard and assistive-technology accessibility evidence.
- Developer ID signing, notarization, clean M1/M5 installation, upgrade, rollback, uninstall, GitHub/Homebrew delivery, and a documented Mac App Store disposition.
- Nexus exact-tuple selection, useful streamed conversation, cancellation, provenance, and explicit no-fallback behavior.
- Privacy-safe support bundle, support matrix, demo runbook, public benchmark packet, claim review, and validated completion proof.

Until that evidence exists, individual tuples remain `research`, `prototype`, or `platform-foundation`; they must not be described as launchable merely because a model produced output or a benchmark passed.
