# Direct task claims acknowledge exact durable source wakes

Integration status: the same-source follow-up in [COMPLETED_TASK_WAKE_EXCLUSION.md](COMPLETED_TASK_WAKE_EXCLUSION.md) now adds typed nonexecuting exclusion for proven old DONE sources. The pre-fix debt section below records the original finding, not a claim that the combined candidate still dispatches completed work. Combined native focused race qualification passed three repetitions on 2026-10-20; protected CI and live rollout remain separate, unfinished evidence.

Refs: ADR-061 durable delivery; Ra source obligation from native wake f2bb365ad9ab948f353d1019d2f191dc readback (task DONE but source wake pending).

An authenticated direct ClaimTask/ClaimNextTask is a genuine executable store action. It does not require a prior supervisor ClaimWakeEvent. Existing task-claim triggers only acknowledge leased wakes; a direct claim can therefore complete real work while its source wake stays pending and ClassifyLane correctly refuses to use it as acknowledged completion evidence.

After the exact actionable task row is successfully leased, the same claim transaction now ACKs only pending/leased wakes with matching agent, source_kind=ledger_task, and source_id=the selected task id. The ACK reference is the existing task-lease reference correlated to the actual newly issued fence. Terminal failure history, existing ACKs and unrelated item/task/agent sources are untouched by this new update. Existing trigger behavior for already-leased lane continuations remains unchanged. No ListWakeEvents grant, manual ACK, readiness flag, schema migration or credential change is involved.

A rejected claim never reaches this update. An ACK write error rolls back the entire task claim and attempt increment. Completion remains separately fenced and requires real result_ref. Claim alone is not successful completion and does not clear terminal failure history.

Both SQLite and Postgres use SQLiteStore.claimTask via the existing dialect/transaction adapter; UPDATE placeholders are rewritten by that adapter. PostgreSQL's existing leased-only trigger remains compatible; the new exact-source transactional update handles pending source wakes without changing database schema or grants.

Fixtures cover direct exact/next claims without any prior wake lease, exact ACK reference, wrong-task/foreign-lane/terminal-history preservation, blocked/missing rejection, simultaneous contenders with only winner ACK, real fenced completion and classifier total-versus-unresolved, and SQLite injected ACK failure rolling back ownership/attempts. The portable fixtures use newTestStore and thus the existing optional Postgres backend harness. The injected SQLite ABORT fixture is explicitly backend-specific. Native Go1.27.1 normal/race qualification and exact source review are required before acceptance; retained cloud Go1.25 cannot compile current main. Existing completed Ra task061814 is not retroactively fabricated into ACKed evidence by this patch.

## Explicit pre-fix pending/DONE wake debt

Native readback983e8543 confirmed old source wake f2bb365ad9ab948f353d1019d2f191dc is still pending/attempts0 for already-DONE task ra-release122-merged-source-readiness-20261020. No old token is reconstructed and no ACK is backfilled by this patch. Inspection of supervisor.go shows ClaimWakeEventFor followed by invocation, and wakeevents.go leases pending events and later expires unacknowledged deliveries into retry/terminal failure; there is no existing typed source-completed disposition in that path. Thus the old row remains explicit residual debt: after a new legitimate completion clears current failures, this old pending/DONE event could later be selected and retried. Native integration must retain and address that debt through a separately reviewed typed source-completed/evidence disposition or source-status dispatch exclusion before claiming the entire wake lifecycle fixed. Do not silently expire/deadletter it, manually set task-lease ACK, delete failure history, or infer an old lease token. This minimal claim-path patch prevents creation of new direct-claim debt; it does not retroactively resolve old rows.
