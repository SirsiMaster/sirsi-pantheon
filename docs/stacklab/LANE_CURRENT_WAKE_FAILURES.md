# Current versus historical terminal wake failures

Refs: ADR-061 durable delivery; existing Ra034034 obligation.

`terminal_wake_failures` remains the complete historical counter. `unresolved_wake_failures` is separate: each terminal failure remains current unless strictly newer durable successful completion evidence exists for that same lane. Both counts derive from the same failure-row read, so concurrent insertion cannot produce an unresolved count larger than its historical total. PID, heartbeat, readiness flag, wall-clock passage and manual reset are not evidence. Equal, absent and malformed timestamps do not resolve a failure. New failures re-block; historical rows are never deleted. Real live fenced work retains WORKING/ASSIGNED priority with completion-integrity debt counted separately. Once no live work remains, completion-integrity failures remain BLOCKED even with runnable work; an unresolved no-work failure is BLOCKED, never COMPLETE.

A completed item must have a nonempty non-placeholder result, a terminal `closed` timestamp and a prior fenced attempt. A task must be done with result_ref, a prior attempt, and a source-correlated acknowledged fenced task-claim wake. Its conservative successful-run lower bound is the earlier of completion-row updated and claim acknowledgement updated. A metadata-only update of an old done task cannot move this lower bound forward and clear a newer failure. This deliberately may retain a failure that occurred after the claim but before completion; schema25 has no immutable task-completed timestamp. A future exact immutable completion audit can improve liveness, but must not replace this bound with mutable task.updated alone. A task completed without an acknowledged source wake is not used to clear historical failures.

Authored fixtures execute real ClaimNextTask/CompleteTaskLease or ClaimNext/Complete transitions in a disposable store; cover newer success with retained total, subsequent failure and metadata touch, equal/malformed/empty failure timestamp, malformed completion, actual thread/heartbeat-only input, no-work BLOCKED and integrity precedence.
