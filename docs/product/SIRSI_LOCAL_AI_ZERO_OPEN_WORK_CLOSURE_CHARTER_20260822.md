# Sirsi Local AI Zero-Open-Work Closure Charter

**Date:** 2026-08-22  
**Scope:** Pantheon, SNE v2, Nexus local AI, Apple-silicon observability, packaging, distribution, and product evidence  
**Completion rule:** no non-owner-gated runnable, stale, hung, or unexplained obligation remains

This charter is the acceptance contract for the active native zero-open-work
goal. The machine inventory and native task plan are its synchronized,
owner-visible projections; none may narrow or silently redefine this scope.

## Canonical unfinished inventory

### A. Pantheon host and product closure

1. Promote the portfolio permission-silence source repair into a stable
   Developer-ID-signed installed package and prove clean-user launch without any
   unsolicited TCC, keychain, notification, OAuth, or protected-resource prompt.
2. Import or otherwise make the Developer ID certificate and private key usable
   through the visible Login keychain; never use hidden release keychains or
   treat sudo as private-key authorization.
3. Finish Homebrew as one unambiguous cask/install/upgrade contract; eliminate
   formula-versus-cask confusion, incorrect `brew upgrade sirsi pantheon`
   guidance, trust-loop friction, and stale binary-drift recommendations.
4. Complete signed update, rollback, uninstall, clean-host, and notarization
   evidence without replacing production with ad-hoc bytes.
5. Prove all menubar findings and alerts have native, typed, receipt-backed
   resolution paths; Terminal is retained only for Apple-owned credential UI.
6. Keep Spotlight the sole broad indexer, Jackal explicit-only, Pantheon memory
   bounded, process ownership singular, and containment-disabled research agents
   retired unless a named test explicitly requires a copied worker.
7. Close optional restart/resume behavior across planned restart, cold boot,
   login, lock, sleep/wake, and cache-clearing modes without promising FileVault
   bypass or automatic GUI login.
8. Close M1/M5 reachability truth: transport, SSH, Screen Sharing, GUI lock, and
   agent-session state are separate signals; idle Tailscale `Active=false` is not
   unreachability.
9. Close Google/Firebase and Seshat authentication recurrence with durable token
   ownership, no repeated browser loops, diagnostics, expiry recovery, and
   privacy-safe support evidence.
10. Reconcile binary drift, optional liveness containment, stale LaunchAgents,
    login items, Full Disk Access entries, keychain search list, and abandoned
    processes so diagnosis reflects intentional state rather than urging repair.

### B. SNE v2 canonical engine closure

11. Treat SNE v2 as the sole active lineage and SNE v1/v145-era packages as
    immutable historical controls, not active product candidates.
12. Recenter implementation on the registered v131 high-water ancestor. Keep
    `131.589 tok/s` scoped to fixed32 engine diagnostics and the historical
    four-arm rate scoped separately; never merge unlike timing contracts.
13. Reconcile the historical 59.185 tok/s macOS 26.5.2 result, current 26.6.1
    approximately 46 tok/s result, and later shared-wide 65-108 tok/s workloads
    by exact OS/runtime/workload identity rather than choosing a favored number.
14. Apply every correctness/usability feature as a copied-candidate ablation;
    reject or repair any descendant that loses unexplained speed.
15. Complete GPU-resident Objective-C++/Metal work-graph decode, optimized
    separate prefill, governed Go orchestration, and explicit plain/MTP profiles.
16. Complete dynamic/paged KV cache, 4K and 8K qualification, then each model's
    declared context where memory, correctness, retrieval, and latency pass.
17. Complete tokenizer, true SSE, cancellation, disconnect, timeout, stop
    sequences, structured output, prefix reuse/invalidation, multi-turn state,
    concurrency, queue fairness, crash/reboot/sleep recovery, and cache safety.
18. Keep Python validation-only and prohibit silent CPU, cloud, model, precision,
    framework, assistant, or cache-contract fallback.

    fresh100; varied100; two-hour and overnight soaks; memory pressure; clean
    process; interrupted download; corrupt artifact; update; rollback; uninstall.
22. Complete Gemma 4 12B affine-8 plain/MTP and supported Q4/Q5/Q6/NVFP4/MXFP8,
    26B-A4B, 31B, then governed catalog models. Keep M1/M5 claims separate.
23. Resolve or formally reject open QMV/QMM/down-family, long-context mask,
    paged-ring, service observer, API4096/8K binder, fairness, and sustained MXFP8

### D. Total-chip observability closure

    rollback, uninstall, security, privacy, accessibility, and support bundles.
34. Complete model checkout catalog, demo, public benchmark packet, support

35. Complete three-home publication for material canon: repository authority,
    Owner Reading Room Markdown/HTML, and native Sirsi Workspace copy or a visible
    connector blocker.
36. Reconcile stale SNE v1 article-review routes as superseded or close them with
    current evidence; do not leave abandoned review work looking active.

## Explicit external or owner gates

These are visible but cannot halt independent execution:

- Developer ID private-key import password or approval in the Login keychain.
- Apple notarization credentials or interactive account approval when required.
- Google/Firebase console changes that only an account owner can confirm.
- Creation of public social/distribution accounts.
- Legal/counsel decisions and investor approvals.
- Unrelated FinalWishes, Assiduous, customer-product, and portfolio workstreams.

## Zero-open-work acceptance

Completion requires each numbered item to have one machine-readable disposition:
`complete`, `superseded`, `rejected-with-evidence`, or `external/owner-gated`.
No `runnable`, `unknown`, `stale`, or `hung` item may remain. The closure audit
must also prove no unexplained Sirsi process, prompt loop, launch item, package
dependency, performance regression, or unmirrored material record remains.
